Lektion 4

Eine Graph Node braucht weniger Daten als du denkst

Ziel: Du definierst die kleinste sinnvolle API für einen Dependency-Graph-Knoten.

Status: begonnen. DependencyGraphNode.tsx existiert, nutzt aber noch SidebarItemViewProps plus uiRes?: any statt einer kleinen graph-spezifischen Node-API.

Nicht das ganze View-Objekt

Eine Node ist ein kleines Anzeigeelement. Sie sollte nicht wissen, wie WebSocket, HUD oder Backend-Modelle funktionieren.

Ein guter Start ist: name, verdichteter status, isSelected, onOpen und optional onRestart. Mehr Daten kommen erst dazu, wenn eine Story sie wirklich braucht.

4-Minuten-Aufgabe

  1. Lies NR/webui/Dependency-Graph-Nodes-und-Storybook.md, Abschnitt „Node-API festlegen“.
  2. Schreibe drei Props auf, ohne die ein Knoten nutzlos wäre.
  3. Schreibe zwei Daten auf, die bewusst draußen bleiben sollten.

Retrieval Check

Warum sollte die Node kein komplettes View kennen?

Sonst koppelt Anzeige an App-Zustand.

Welche Prop öffnet später die Detailansicht?

onOpen.

Welche Prop schützt die Auswahldarstellung?

isSelected.

Primärquelle

Nutze NR/webui/Dependency-Graph-Nodes-und-Storybook.md als Lernquelle. Für Custom Nodes siehe React Flow Custom Nodes.
